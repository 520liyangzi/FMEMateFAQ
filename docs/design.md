# 功能导航的匹配设计

## 问题与输出

本项目解决的是“工程师想查某些信息，应该输入哪些预置问题”，输入依据是 Excel 维护的能力目录。目标输出包括：

1. 拆分后的具体需求。
2. 推荐的中文、英文触发问题。
3. 每项需求匹配到的对象、字段和来源行。
4. 能覆盖这些需求的功能组合，以及尚未覆盖的需求。

例如“端口的收发光功率和 GNSS 工作模式”包含接收光功率、发射光功率、GNSS 工作模式三项需求。如果分析工单覆盖三项，就选择一个分析工单功能；如果清单只提供两个独立功能，则组合两个功能。没有匹配到的需求保留在结果里。

软件不查询当前光功率数值，不生成真实拓扑图，也不判断故障根因。清单只有字段名称时，软件无法推断未写明的产品版本、网络环境、接口权限或数据前提。

## 数据关系

目录保留三层关系：

| 层级 | 主要内容 | 用途 |
| --- | --- | --- |
| 功能 | 中文、英文触发问题 | 工程师最终可输入的问题 |
| 对象 | 中文、英文对象名称 | 保留字段所属的业务上下文 |
| 字段 | 中文、英文字段名称 | 证明该功能可以提供的信息 |

对象和字段属于具体功能，不把同名短字段自动合并到全局对象。每层都有稳定 ID 和来源位置，重复行在同一完整路径内去重。

Excel 纵向合并展开时保留单元格来源行。普通空白只在当前父级内延续：切换问题会清空对象上下文，切换对象不会继承上一个对象的字段。跨越父级边界的异常合并不会把旧子级带入新分组。

导入分为预览和确认两步。预览仅生成候选目录，显示统计、警告、工作表和列映射；确认后才替换当前目录。当前版本一次处理一个工作表，不做多文件增量合并。

## 本地匹配流程

### 1. 拆分需求

规则识别中文、英文连接词和分隔符，并展开常见组合，如“收发光功率”展开为接收、发射光功率。查询中无法识别的内容仍作为需求保留。

可选 Claude 模式帮助处理更自然的表达。模型输出的需求仍交给本地匹配器，并保留原始查询中本地识别出的内容，避免模型只选取容易命中的需求。

### 2. 找到可核对的能力证据

先按完整表述、专业词别名、中英文字段名称匹配。字段证据包含所属对象，例如“GNSS 信息 / 工作模式”，避免只按“工作模式”三个字混淆不同对象。

别名字典明确维护中文、英文和缩写之间的对应关系。例如“驻波比”“VSWR”属于同一概念，“接收光功率”和“发射光功率”属于不同概念。别名不会为清单增加不存在的能力。

每项命中保留对象、字段、匹配方式及来源位置。覆盖率是“已匹配需求项数 / 本次需求项数”，表示匹配证据的覆盖程度，不是模型置信度或实际故障处理成功率。

### 3. 选择功能组合

将每个功能看作一组能够覆盖的需求，选择覆盖已知需求且使用功能数尽量少的组合。这是集合覆盖问题，与是否使用向量数据库无关。

需求不超过 18 项且去除冗余后的候选不超过 120 个时，使用精确动态规划；若中间状态超过 50000 个，则改用有界的贪心搜索。更大输入直接使用近似搜索，界面会提示可能存在更少的功能组合。精确求解针对本次成功匹配的需求，不会把未知项假设为已经覆盖。

单项功能还会按覆盖需求数量排序。覆盖相同时，倾向对象较少的聚焦功能。组合和单项推荐均保留证据，便于维护清单或补充别名。

## 为什么首版不用向量数据库

当前信息由较短的名称和明确层级组成，主要挑战是保留关系、处理中英文别名、拆分多需求，并计算覆盖组合。向量化不是这几个步骤的前提。

单独向量化“柜号”“槽号”“工作模式”等字段会丢失父级上下文。相似度高也不能证明两个字段业务含义相同，更不能证明一个功能覆盖全部需求。首版使用可检查的本地证据，减少配置和公司网络依赖。

以下信号出现后，可以考虑补充向量召回：

- 工程师长期使用与清单差异较大的表达，别名维护仍无法覆盖。
- 目录加入较长的功能说明、故障现象或业务场景描述。
- 真实查询评估显示，本地匹配经常遗漏本来存在的功能。

届时建议把一条完整路径作为检索文档：

```text
触发问题：请帮我分析一下这个工单 / Help me analyze this ticket
对象：GNSS 信息 / GNSS information
字段：工作模式 / Working Mode
别名：GNSS 工作模式、GNSS operating mode
```

向量检索先提供候选，随后核对目录证据，再计算功能覆盖组合。评估需要真实查询、人工标注的目标功能和应保留的未知需求，并分别观察召回、误推荐、额外模型依赖和响应耗时。当前版本没有实现向量库，也没有未经测量的性能结论。

## AI 的边界

AI 是可选的需求理解器。它帮助把一句话拆成字段或对象需求，不直接决定清单里有什么能力，也不替代功能组合计算。

公司无 API 的情况下，软件可以调用本机已登录的 Claude CLI。默认关闭，通过参数数组启动，提示词从标准输入传入。失败时显示原因并退回本地匹配。具体参数和联调限制见 [claude-cli.md](claude-cli.md)。

由于没有提供真实客户 Excel，也没有可用的公司 Claude 登录环境，当前验证针对合成工作簿、本地推荐逻辑、受控子进程和 HTTP 接口。真实导入时应先检查预览，再用代表性需求核对推荐依据。

## 运行与维护

- Python 本机 HTTP 服务加静态浏览器页面，默认地址为 `127.0.0.1:8765`。
- 目录、别名、设置集中保存在 `data/state.json`，用临时文件和原子替换减少保存中断造成的数据损坏。
- 确认导入会替换目录，支持 JSON 导出用于查看和备份。
- 原始工作簿不持久保存，运行数据和 Excel 文件不提交到公开仓库。
- 维护重点是让真实功能清单和环境版本保持一致，以及用误匹配案例完善对象名称和别名。
