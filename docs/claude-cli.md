# 使用公司 Claude CLI 增强需求理解

软件默认使用本地规则，无需 API Key。可选的 Claude 增强调用本机已经安装、登录并配置好公司模型的 `claude` 命令。本地先拆分原始需求，模型只按原顺序逐项规范化术语，功能是否存在、覆盖哪些字段仍由导入目录和本地匹配确定。

## 配置

1. 在启动软件的同一账户和终端环境中，先确认 `claude` 能正常使用，并按公司要求完成登录。
2. 在软件的“别名与 AI”页面开启 Claude 增强。
3. 命令使用 JSON 字符串数组，默认 `["claude"]`。如需指定路径或公司模型，可以填写 `["/absolute/path/claude", "--model", "your-company-model"]`。每个参数独立一项，不填写管道、重定向或整行 shell 命令。
4. 超时时间默认 45 秒，可设为 5 至 120 秒。
5. 查询时勾选 AI 增强。未勾选时，软件始终只运行本地检索。

Windows 的 npm 标准 `claude.cmd` 安装会自动转成同目录下的 Node `cli.js` 入口运行。自定义 `.cmd` / `.bat` 包装器不直接执行；请配置原生 `.exe`，或 `["node", "C:\\path\\to\\cli.js"]`。如果使用公司包装器，它需要支持下述 Claude Code 非交互参数并把 JSON 响应输出到标准输出。

## 调用方式

软件用子进程运行以下等价命令，提示词从标准输入传入：

```text
claude -p --output-format json --tools "" --disallowedTools "*" --no-session-persistence --strict-mcp-config --mcp-config '{"mcpServers":{}}' --setting-sources user --settings '{"disableAllHooks":true}'
```

以上代码用于说明参数，不必手动复制到 Windows CMD。软件直接传递参数数组，`shell=False`，不会把用户问题拼成命令。

每次使用独立临时目录，保留当前账户和终端的认证环境，不给模型配置读文件、执行命令或 MCP 工具。额外设置禁用本次调用的 hooks；公司管理策略仍以公司的实际 CLI 行为为准。`--no-session-persistence` 不保存可恢复的 CLI 会话，但不改变公司模型网关自己的日志策略。

发送给公司 CLI 的内容包括当前问题、`original_requirements` 原始需求列表，以及不超过约 60 KB 的目录术语（触发问题、对象和字段），不包括原始工作簿、项目源码或本机其他文件。超大目录只发送前部术语，模型仍需逐字保留无法确定等价术语的未知需求，软件本地检索始终使用完整目录。

响应需要包含 `{"requirements":["端口接收光功率","端口发射光功率","GNSS工作模式"]}`，与原始需求严格按位置一一对应，禁止添加、删除、合并、拆分和重排。软件校验数量完全一致并拒绝重复规范化结果，防止原始需求被合并。原始需求文本仍用于展示，AI 规范化文本作为附加说明。一次 AI 增强最多支持 20 项需求。

同时兼容 Claude `--output-format json` 的外层 `result` 字段和 JSON 代码块。无效响应、数量不符、重复输出、未登录、命令不存在或超时会显示原因，并回退到本地检索。数量校验无法证明语义完全等价，仍需结合页面展示的原始需求和规范化文本判断是否符合预期。

## 排查

- 提示找不到命令：从能够正常运行公司 Claude 的终端启动软件，或填写完整可执行路径。
- 提示登录或认证失败：在本机终端按公司的流程重新登录；软件不索取或保存密钥。
- 提示不支持参数：升级公司允许使用的 Claude Code 版本，或提供兼容非交互模式的包装器。只有交互界面的公司客户端无法直接用于此适配器，仍可使用本地推荐。
- 超时：先在终端确认公司网络和模型可用，再调整超时时间。超时会终止本次 CLI 子进程树。

## 验证范围与参考

开发环境没有安装或登录公司的 Claude，因此验证包括参数传递、JSON 解析、错误处理和超时终止的自动测试，未声称完成公司网络中的端到端调用。需要在实际公司环境首次启用时验证。

参数依据：[Claude Code 官方 CLI reference](https://code.claude.com/docs/en/cli-reference)，核对日期 2026-10-24。文档说明 `--tools` 只限制内置工具，因此软件同时拒绝 MCP 工具，并使用空的严格 MCP 配置。
