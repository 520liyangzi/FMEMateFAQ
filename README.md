# FMEMate 功能导航

把 FMEMate 的“预置问题 → 数据对象 → 字段”Excel 清单变成可查询的功能目录。代维工程师描述想看的信息，软件推荐能够覆盖这些需求的预置问题，并展示对象、字段和 Excel 来源行。

例如输入：

> 我想查端口的收发光功率和 GNSS 工作模式

软件会分别识别接收光功率、发射光功率、GNSS 工作模式。如果导入清单表明“请帮我分析一下这个工单 / Help me analyze this ticket”同时包含这些内容，就优先用这一个功能覆盖需求；需要多个功能时，给出组合方案。目录里没有的内容会列为未覆盖。

当前版本提供功能导航，不连接工单系统、网管接口或故障诊断服务。推荐结果表示导入清单中的能力覆盖关系；实际环境、产品版本和数据可用性仍需与清单保持一致。

## 启动

需要 Python 3.10 或更高版本。

### Windows

1. 下载本仓库 ZIP 并解压到一个固定目录。
2. 首次运行 `install.bat` 安装依赖。
3. 双击 `start.bat`，浏览器会自动打开 <http://127.0.0.1:8765>。
4. 保留启动窗口，按 `Ctrl+C` 停止服务。

后续使用直接运行 `start.bat`。依赖安装需要能访问公司允许的 Python 包源；运行本地匹配不需要外网或 API Key。

### macOS / Linux

```bash
python3 -m pip install -r requirements.txt
python3 app.py
```

服务器只监听本机 `127.0.0.1`。如果端口被占用，可运行：

```bash
python3 app.py --port 8766
```

无桌面环境或不希望自动打开浏览器时，加上 `--no-browser`。数据默认写入项目目录下的 `data/state.json`，可使用 `--data-dir /path/to/data` 指定其他目录。

## 先体验，再导入

首次启动会显示人工编写的演示数据，页面明确标记“当前为示例数据”。演示目录只用于验证软件流程，不代表真实 FMEMate 产品能力。

1. 在“需求推荐”输入“端口的收发光功率和 GNSS 工作模式”。
2. 查看推荐的中英文触发问题、每项需求的匹配依据及未覆盖项。
3. 进入“导入 Excel”，选择自己的文件，点击“识别并预览”。
4. 检查工作表、六列映射、识别统计、警告和问题层级。
5. 确认后替换当前目录，再用真实需求验证结果。

一次导入一个工作表，确认导入会替换当前整个目录。多个工作表时，可在预览后切换工作表重新识别；当前版本不自动合并不同工作表。替换前可用页面上的“导出目录”保留 JSON 快照，或自行备份 `data/state.json`。

目前尚未提供你的实际工作簿，开发验证使用人工构造的合并单元格、空白行和中英文测试样例。首次真实导入请重点检查预览中的对象归属和字段数量。

## Excel 格式

支持 `.xlsx`、`.xlsm`、`.csv`，最大 20 MB。`.xlsm` 只读取数据，不运行宏；旧版 `.xls` 请另存为 `.xlsx`。CSV 支持 UTF-8 和 GB18030。

默认六列如下，也可以在“工作表与列映射”中按实际列号指定。列号从 1 开始，A 列为 1。

| 列 | 内容 | 示例 |
| --- | --- | --- |
| A | 触发问题中文 | 请帮我分析一下这个工单 |
| B | 触发问题英文 | Help me analyze this ticket |
| C | 对象中文 | 故障端口表 |
| D | 对象英文 | Faulty port table |
| E | 字段中文 | 接收光功率 |
| F | 字段英文 | Receive Optical Power |

导入规则：

- 自动在前 50 行中识别表头；也可以手动填写表头行号，`0` 表示没有表头。
- 读取真实的纵向合并单元格；同一分组中留空的问题、对象会按当前层级延续。
- 新问题会重置对象，避免把上一个问题的对象或英文名称带入新分组。
- 全空分隔行会重置当前层级，分隔行之后需要重新填写问题和对象。
- 字段不做普通空白向下填充。无字段的对象仍保留，可按对象名查找。
- 支持只填写中文或只填写英文。中英文合并范围不一致时，会忽略不可靠的继承值并提示确认。
- 同一层级内重复内容去重，保留来源行。公式和 Excel 错误值所在行会跳过并显示警告。
- 数据区跨越多个语义列的横向合并会被拒绝，需要先取消横向合并。

为了控制导入资源，工作簿最多 20 个工作表、总计 100000 行、256 列，解压后最多 120 MB。文件超限时可删除无关工作表和多余行列格式后重试。

## 是否需要向量化或 AI

当前默认不做向量化，也不要求 AI。你的核心数据是短字段和明确的层级关系，“收发光功率”可以拆成接收、发射两个需求，再通过中英文和专业词别名匹配到字段，最后计算哪些功能能够一起覆盖需求。

向量检索主要帮助找到表述不同但语义相近的候选项，不能代替“一个功能能否覆盖所有需求”的判断。直接把“工作模式”“槽号”等短字段独立向量化，还容易丢失 GNSS、端口或单板等上下文。后续如果真实查询经常无法命中，并且补充别名仍不足，可以用“问题 + 对象 + 字段 + 别名”作为向量检索单元，并用真实查询样本评估召回效果。详细设计见 [docs/design.md](docs/design.md)。

### 专业词别名

“别名与 AI”页面可以编辑 JSON 字典。例如把“驻波比 / VSWR / Voltage Standing Wave Ratio”放在同一个概念中：

```json
{
  "groups": [
    {
      "canonical": "vswr",
      "terms": ["驻波比", "VSWR", "Voltage Standing Wave Ratio"]
    }
  ]
}
```

保存会替换当前完整别名字典，请在页面现有内容中添加或修改分组。别名用于解释同一个概念，不会凭空增加清单中的功能。项目中的 `config/aliases.json` 提供初始默认值；页面保存后的设置位于 `data/state.json`，重启后继续生效。

### 可选 Claude CLI

如果公司环境里已经能启动并使用 `claude`，可以在“别名与 AI”中启用它，再在查询时勾选 Claude 增强。默认命令配置为 `["claude"]`，无需本软件配置 API Key。

Claude 按原始需求逐项归一化自然语言表达，推荐结果仍需本地目录给出匹配证据。页面同时显示原始需求和 AI 归一化词。已有本地匹配的需求保持原词，AI 少返回、多返回或合并需求时会回退本地规则。语义改写仍可能出错，请核对显示的归一化词。命令不存在、未登录、响应异常或超时时，会提示原因并回退到本地规则。

实际公司 CLI 尚未在开发环境中完成联调。参数、Windows 路径、发送内容与排错方式见 [docs/claude-cli.md](docs/claude-cli.md)。

## 数据保存

导入后的目录、别名和 Claude 设置保存在本机 `data/state.json`，刷新页面和重启软件后会恢复。原始 Excel 不写入 Git 仓库，软件也不保存一份原始工作簿副本。

`data/`、Excel 文件等运行数据已配置为 Git 忽略项。请不要把真实客户清单、公司配置或其他内部数据提交到公开仓库。需要备份时自行保管数据目录。

## 开发与验证

```bash
python -m unittest discover -s tests -v
```

测试覆盖导入层级及合并边界、中英文匹配、多项需求覆盖、未知需求保留、CLI 响应处理与服务接口。测试使用合成样例和可控子进程，不代表已经验证真实客户工作簿或公司 Claude 服务。

主要文件：

| 路径 | 职责 |
| --- | --- |
| `app.py` | 本机服务启动入口 |
| `fmemate/importer.py` | Excel / CSV 识别与导入预览 |
| `fmemate/matcher.py` | 需求拆分、证据匹配、功能组合 |
| `fmemate/claude_cli.py` | 可选公司 Claude CLI 适配 |
| `fmemate/storage.py` | 本地 JSON 原子保存 |
| `fmemate/server.py` | 本机 HTTP 接口 |
| `static/` | 浏览器界面 |
| `config/aliases.json` | 默认中英文专业词别名 |
| `tests/` | 自动化验证 |
